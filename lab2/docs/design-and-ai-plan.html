Soonish: design and AI plan

Lab 2, Part 1. Sitemap, rough designs, content plan and the planned AI feature.

Sitemap

Every page links to every other page through the shared navigation.

  • index.html: introduce Soonish and send people to the next step.
  • problem.html: explain food waste with sourced facts.
  • how-it-works.html: show the label, watch and pass-it-on habits.
  • shelf-guide.html: look up how long food lasts and what dates mean.
  • fridge-rules.html: print the rules a floor can agree on.
  • ai-rescue.html: read the plan for the AI feature.
  • about.html: see the goal and the source of every image.
  • contact.html: send feedback through a labelled form.

Rough designs

Design choices

The look comes from a real dorm fridge: cold pale shelves, masking-tape labels and marker handwriting. Colours are defined once in CSS variables. Headings use a slab serif, text uses a clean sans-serif, and the handwritten font appears only on labels.

What users can do on the finished website

  • Learn why food waste matters and how a shared fridge adds to it.
  • Look up storage times and print fridge rules.
  • Later: add food, see dates, and pass food on to neighbours.
  • Later: ask for a recipe built around the most urgent food.

AI plan: Rescue Recipes

PurposeHelp students cook food close to its date instead of throwing it away.
InputItems expiring within two days, their portions, and an optional diet choice.
OutputUp to three cheap recipes. Each one uses the most urgent item first and lists what is missing.
Place on the siteA Rescue button above the shared fridge list. Results open in a panel.
ApproachConnect an API and use an existing model. We will not train a model, because we have no recipe data set and a general language model already knows cooking.
Model or serviceClaude through the Anthropic Messages API, with a small fast model such as claude-haiku-5-5.
Integration planThe browser sends the item list to a small server. The server keeps the secret API key, adds instructions, calls the model and returns the recipes as JSON. The website then renders them as cards.
Main limitsThe model can make mistakes, cannot judge if food is safe, and does not know allergies unless told. Each request costs money and needs internet access. Labs 2 and 3 do not allow a backend, so the feature stays a plan.
